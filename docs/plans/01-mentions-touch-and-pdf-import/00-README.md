# 01 — Editor mentions, touch UX, and PDF import fidelity

Master plan: [`../../PLAN.md`](../../PLAN.md)

## Goal
- A user selects lines in Monaco and sends them to the agent as an explicit, visible **@mention** — via a floating button on the selection, `Ctrl/Cmd+M`, or the mobile touch callout — so the agent edits exactly the lines the user means.
- Mentions actually reach the agent's reasoning. Today `selection` is plumbed end to end but is read only by `elaborate.py`; it never enters the main prompt.
- Mobile gets undo/redo (it currently has none) without adding permanent chrome.
- Copy/paste stops failing intermittently, on touch and on desktop.
- A compile that fails on the first click but succeeds on retry stops happening, and when the server is busy the UI says so instead of claiming the LaTeX is broken.
- A 33-page PDF import no longer dies with "This conversion job no longer exists", and can resume.
- PDF→LaTeX gains a **template mode**: a student uploads a lecturer's seminar-report template and gets an editable document that keeps the fonts, sizes, colours, margins and every asset.

## Decisions (already made; do not revisit)

| # | Decision |
| --- | --- |
| M1 | **Mention data model.** `MentionRef = { id: string; file: string; start_line: number; end_line: number; text: string; label: string }` in a new `lib/mentions.ts`.<br>`label` is rendered on the chip and is `` `<basename> L<start>` `` for one line, `` `<basename> L<start>–L<end>` `` otherwise.<br>`id` is `` `${file}:${start_line}:${end_line}` ``; adding a mention with an existing `id` replaces it rather than duplicating.<br>At most **8** mentions per message; adding a 9th shows `toast.error("You can mention up to 8 selections.")` and is a no-op. `text` is truncated to **4000 characters** per mention (append `\n…` when truncated). |
| M2 | **Mention triggers.** (a) Desktop: whenever the active editor's selection is non-empty, a Monaco **content widget** floats just above the selection start showing a single `@ Mention` button; it hides on empty selection, on scroll past the viewport and while the agent is streaming.<br>(b) Keyboard: `Ctrl/Cmd+M` via `editor.addCommand` registered beside the existing Ctrl+S binding, on **both** editor instances.<br>(c) Mobile: an `@` button in the existing `MobileEditorAssist` callout, left of Copy, shown only when the selection is non-empty.<br>All three call one `addMention()` callback owned by `EditorLayout`. Chips render in a row directly above the chat textarea in both the desktop and mobile chat forms, each with an `×` to remove. The list clears after a successful send and on project change. |
| M3 | **Wire format.** The `/api/agent/run` request body gains `mentions: MentionRef[]` (omitted when empty). The existing `selection` field keeps its current shape and meaning for back-compat; when `mentions` is non-empty, `selection` is set to the **first** mention so `elaborate`/`humanize` keep working unchanged. |
| M4 | **Agent behaviour — steer, do not restrict.** `OpenCodeRequest` gains `mentions: Optional[List[Dict]]`, passed through `stream_agent(mentions=...)` to the loop. When present, a `<mentioned_context>` block is appended to the **first user message** listing, per mention, `file`, `lines start-end` and the verbatim text in a fenced block. The system prompt gains exactly one instruction: treat mentioned ranges as the primary edit target, and edit outside them only when the change requires it (preamble, package, environment closure). **No `edit_validator` restriction is added** — out-of-range edits stay legal. |
| M5 | **Mobile undo/redo.** Undo and Redo buttons are added to the `MobileEditorAssist` callout, left of Copy, and are always present (not only when text is selected). They call new `onUndo` / `onRedo` props that `EditorLayout` wires to its existing `handleUndo` (:1361) and `handleRedo` (:1368), so the Yjs-aware undo path is reused. They render disabled (40% opacity, `aria-disabled`) when the corresponding prop is absent. No new toolbar, pill, or header button is added anywhere. |
| M6 | **Clipboard write.** `copyText` in `lib/clipboard.ts` is restructured so no `await` happens before a fallback can run: it calls `navigator.clipboard.writeText(text)` synchronously, and **on rejection** immediately tries the synchronous `execCommand("copy")` textarea path, and if that also fails resolves `false`. Every call site must act on the boolean: on `false`, open a **manual copy sheet** — a focused, selected, read-only textarea mirroring the existing paste fallback — so the user can always complete the copy. `handleCopy`/`handleCut` in `MobileEditorAssist` currently discard the result (:397, :406); they must not. |
| M7 | **Clipboard paste and selection stability.** The touch-only native `paste` interceptor at `EditorLayout.tsx:1777-1815` is **removed**: it calls `preventDefault()` + `executeEdits` + `handleCodeChange(getValue())`, bypassing the collab binding and desyncing the room. Paste routes through Monaco's own handling so the binding observes it. The dead `handleCustomCopy`/`handleCustomPaste` at `EditorLayout.tsx:1287-1330` are deleted. In `lib/collab/monaco-binding.ts`, the remote-update path must never call `model.setValue` (:307) while the local selection is non-empty — apply a diff via `applyEdits` and restore the prior selection afterwards. |
| M8 | **Compile: distinguish busy from broken.** `/api/compile` already returns **429** `{detail, retry_after_seconds}` when the queue is full, and the frontend (`EditorLayout.tsx:1925-1930`) turns any non-success body into `"Compilation failed."`, hiding it. The frontend must branch on `res.status`: on 429 it shows `toast.loading("Server busy — retrying…")` and auto-retries up to **3** times with 1s/2s/4s backoff before surfacing `"Server is busy. Try again in a moment."`; it must **not** set `errorLog`. Only a `200` with `success:false` sets `errorLog`. Network errors keep today's message. |
| M9 | **Compile: flush collab before compiling.** `compile_endpoint` in `main.py` awaits a flush of the project's collab room (the debounced persist in `collab/room.py` is 2.0s idle / 15s max) before submitting to the queue, so sibling files — `\input` chapters, `.bib` — are read fresh from `uploads/projects/<id>/` rather than stale. The flush is best-effort: a missing room or an error is logged and compilation proceeds. The hard-coded `"main.tex"` skip at `compiler.py:1311` is **not** changed. The default `timeout_seconds` at `compiler.py:1221` rises **30 → 60** to absorb a cold TeX format/font cache on the first compile after boot. |
| M10 | **Job store durability.** `PDF2LATEX_JOB_DIR` defaults to `<repo>/uploads/pdf2latex_jobs` instead of `tempfile.gettempdir()/overbranch_pdf2latex_jobs` (`pdf2latex/config.py:66`). Only `./uploads` is bind-mounted (`docker-compose.yml:24`, `:51`, `docker-compose.backend.yml:19`), so today's default lives in the container's ephemeral `/tmp` and is destroyed when uvicorn recycles (`entrypoint.sh:39`, `--limit-max-requests 10000`) or the container restarts. `.env.example:98` is updated with the new default documented. `purge_old_jobs` and `JOB_TTL_S` are unchanged. |
| M11 | **Job resume and honest status codes.** `_owned_job` (`routes/pdf_convert.py:65`) today returns **404 "Conversion job not found."** both when the job is missing and when the owner does not match. Split them: unknown id → `404 {"code":"job_unknown"}`; owner mismatch → `403 {"code":"job_forbidden"}`. On a GET for a job whose directory exists, whose status is non-terminal, and for which `runner.is_job_running(job_id)` is `False`, the route relaunches it with `runner.start_job(..., resume=True)`; the pipeline skips pages already `status=="done"` in `status.json` and reuses their saved `.tex`. A resumed job sets `message="Resuming after an interruption…"`. |
| M12 | **Frontend job polling.** `usePdfConversionJob.ts:186` stops polling and shows `"This conversion job no longer exists."` on **any** 404. Replace with: `job_unknown` → stop, `"This import expired or was removed."`; `job_forbidden` → stop, `"You no longer have access to this import."`; any network error or 5xx → **keep polling** with backoff doubling from `POLL_MS` to a 10s cap, giving up only after **20** consecutive failures with `"Lost contact with the server. Your import may still be running — reopen this project to check."` |
| M13 | **Template mode.** `POST /api/convert/pdf` gains `mode: "exact" \| "template"`, default `"exact"`; `"exact"` is today's pipeline, byte-for-byte unchanged, so `test_pdf2latex_fidelity.py` stays green. `"template"` adds a style-profile pass producing `StyleProfile = { body_font, body_size_pt, line_spacing, margins_mm: {top,bottom,left,right}, colors: [hex], heading_levels: [{ name, font, size_pt, bold, italic, color, spacing_before_pt }] }`, derived from the span data already captured by `extract.py:_extract_lines` (:129) and classified by `fontmap.font_class`. `preamble.build_preamble` (:112) emits it as a **commented, semantic** block defining `\obBodyFont`, `\obHeadingI..\obHeadingIII`, `\obAccentColor` and the `geometry` margins; body text is rendered with those commands instead of per-span inline `\fontsize`/`\color`. |
| M14 | **Template-rule detection.** In template mode only, one extra LLM call over the text of the first **≤3** pages asks whether the document *states* formatting rules (e.g. "Times New Roman 12pt, 1.5 line spacing, 1 inch margins"). It returns strict JSON `{ "is_template": bool, "rules": { ...StyleProfile subset... }, "evidence": [string] }`. When `is_template` is true, **stated rules override measured ones** in `StyleProfile`, and the result is stored at `report.template_rules` and surfaced in the import preview as "Template rules detected". A malformed or failed response is logged and ignored — it never fails the job. |
| M15 | **Asset parity.** Template mode reuses the existing image and vector-art extraction (`extract.py:_extract_images` :475, `_rasterize_vector_art` :529) and the same `assets/pdf_<job8>/` output path, with no change to `storage.write_output_to_project` (:66). Acceptance asserts the **same number of asset files** for a given PDF in both modes. |

## Open follow-ups (not defects in this plan)
- **A secondary body size is not modelled.** On the real lecturer template, 113 of the 205 remaining inline `\fontsize` uses are a single systematic group at **10bp**, plus 39 at 11bp and 40 at 12.5bp (the 0.5pt tolerance edge). `StyleProfile` models one body size and three heading levels (M13), so a document with a second standing body size still inlines it. Covering it needs a fourth semantic style or a secondary-body concept — a product decision, deliberately not scope-crept by slice 12.
